# Platform security, privacy and fund protection

Version 1.1 — 16 October 2026. This is an evidence register, not an independent audit or a promise of absolute safety. It covers the five independent investment repositories and their INFRA UAT deployment. Update this document and its private Notion copy with every material security decision, verified control, remediation or open risk. Automated checks, coordinator-verified runtime checks and remaining user acceptance are recorded separately below.

## Data boundaries

Blockchain wallet addresses, token ownership, trades, funding, claims, privileged wallet roles and approved public metadata are public. They cannot be made private by hiding a UI element. A public reference hash can still permit correlation. No personal profile, identity document, support message, access token, password, private legal document or confidential report may be placed in contract storage/events or public IPFS. Public project media requires an explicit publishing acknowledgement. Personal information stays in authenticated backend storage with explicit response allowlists and tenant authorization. The indexer stores public chain facts only.

The Notion project and Documents library remain private. Actual development credentials are restricted to the dedicated private Development Credentials page and protected runtime injection. They are excluded from Git, general documents, task records, client artifacts, browser storage, generated bundles and logs. Existing development/testnet credentials are authorized for UAT; production requires rotation and a separate release review.

## Architecture and coding practices

Each service has its own repository, lockfile, environment, CI and release identity. Contract ABI snapshots are versioned and checksum validated against an exact contract source commit. Boundaries separate transport controllers, application authorization/commands, domain rules, provider adapters and persistence. Public DTOs explicitly select fields; raw database records containing identities or tokens are never public API contracts. Financial amounts and quantities use decimal strings/BigInt and exact atomic units, never floating-point accounting.

The blockchain is the authoritative ownership/funds ledger. The database is a recoverable projection and application record. Neither a user-entered deposit amount, provider broadcast status nor an indexer estimate can credit funds or declare transaction success. Confirmation, indexing freshness and unavailable providers have distinct UI states. Configuration fails closed on unsupported networks, assets, ABI versions, missing deployments or absent dependencies.

## Fund controls — implemented locally in contracts

- ERC1155 whole fractions, one token ID per immutable project clone. Only exact paid primary purchases issue fractions. Caps, divisibility, quote/deadline and supported-asset checks are enforced on-chain.
- Separate native reAED and USDT ledgers for sale proceeds, funded rewards and marketplace seller proceeds. Claims and withdrawals cannot spend another ledger's liabilities.
- Scaled reward checkpoints settle before minting and transfers. Earlier holders retain allocated rewards after a partial or full exit. Late buyers receive no old deposits. Per-deposit division dust and wallet subatomic accrual are retained permanently; no rescue/expiry/redirect power exists.
- OpenZeppelin ERC1155/SafeERC20 and reentrancy guards, checks-effects-interactions, exact token balance checks, failure-atomic native payouts and fixed entitled recipients.
- Noncustodial resale with live balance/approval/expiry/remaining checks, exact payments and seller-only pull withdrawals. Zero platform fees. No guaranteed buyback, principal redemption or instant resale.
- Two-step owner/treasury changes, revocable creators/finance roles and delayed future implementation activation. Emergency pauses cover new purchases/funding/listings/fills; historical claims and fraction transfers remain available.

Evidence at this stage: 39 local contract tests, exact eager reference-model invariants (extended 512 runs x 256 calls per invariant), fuzzing, gas/coverage reports, source/dependency/ABI checksum checks, and Slither with zero High findings. Deliberate floor-accounting Medium findings and bounded-loop/deadline findings are triaged in the contract repository. The exact reviewed core source is published as 1eee1442c83ee037ee1564d0d3da64d36c370e76. Base UAT deployments have verified receipts/hashes; project and funded user lifecycle acceptance remain open.

Test evidence covers these boundaries; it does not establish exhaustive attack resistance. Public catalog serializers and Pinata publishing still require cross-service content/privacy acceptance.

## Indexer controls — source, hosted CI and bounded runtime readiness verified

Only confirmed canonical blocks are committed. Headers, emitter-verified decoded events, activity, projections and cursor advance commit atomically. A PostgreSQL advisory lock excludes competing workers. Event identity deduplicates replay. Parent hashes, receipt/log hashes and batch-tip rechecks detect inconsistent providers. Reorganizations delete orphaned records and rebuild projections from retained events. Internal call traces reject reverted ancestors, delegate-value duplication, self transfers and duplicated top-level transfers. Canonical snapshots reconcile balances and claimable rewards at the same confirmed block.

Evidence: **43 unit tests and 4 real PostgreSQL integration tests**, including historical rewards, rounding, partial resale, traces, interruption/restart/reorgs, locking, duplicate replay, rollback and cursor atomicity. [e3c6d42](https://github.com/reIDentity/ReSystem-Investment-indexer/commit/e3c6d42b8a97583c74567631ac826e8f2e433bbb) requires canonical successful receipt proof before normalizing INFRA UNKNOWN creation roots, rejects mismatched destinations before committing a cursor and suppresses failed receipt subtrees. The PostgreSQL regression verifies retry and receipt/history/trace deduplication. Hosted [CI run38890730158](https://github.com/reIDentity/ReSystem-Investment-indexer/actions/runs/38890730158) is green. Earlier independent review corrected cancellation event ordering and bare INFRA trace frames. Native and USDT source coverage is independent of internal tracing: a verified native page had six candidate blocks/five successful activities; the USDT page was empty. Historical internal block7121280 returned RPC -32603, so that source remains explicitly partial with retry backoff. All four actual deployment runtime hashes and factory binding are checked before indexing. These checks do not prove a healthy deployed worker, complete historical coverage or full deployed-project accounting/reconciliation; the FP indexer rollout and funded lifecycle evidence are tracked separately.

Published follow-up [8bd7acb](https://github.com/reIDentity/ReSystem-Investment-indexer/commit/8bd7acb0f8c279a3c90f462a7a0ee3a4be2e91f8) additionally accepts only receipt-proved, valid-identity, explicit-zero UNKNOWN leaves with no error or children. It emits no transfer and infers no opcode; unknown positive/missing value, missing proof and UNKNOWN subtrees still reject without cursor advance. Its 43 unit/four real PostgreSQL tests and hosted [CI run #4](https://github.com/reIDentity/ReSystem-Investment-indexer/actions/runs/38893050914) passed.

- Independent audit of the exact smart-contract release commit, remediation and regression checks.
- Project-level INFRA token/gas/finality and receipt/reconciliation acceptance throughout the full financial lifecycle; preserve the already verified base-contract deployment receipts, runtime hashes and immutable manifests.
- Full browser-to-wallet approval-to-receipt-to-indexer lifecycle on UAT, including rejected/expired/failed/racing transactions.
- Cross-service privacy review: unauthenticated endpoints, IDOR, exports, public IPFS contents, logs, generated browser bundles and backups.
- Production-scale recovery and offsite/retention/alert checks, operational access review and indexer restart/reorg/load acceptance; retain the bounded HTTPS/staff-auth/investor-read/database-ACL/encrypted-restore and indexer-readiness evidence without treating it as complete operational acceptance.
- Production credential rotation, appropriate signing governance and explicit production release approval.

Do not call any open gate complete until evidence exists. Keep substantive limitations visible to the client without exposing private implementation details or secrets.
