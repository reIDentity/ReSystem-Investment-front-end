The review found two upstream defects, now addressed by the reviewed and deployed narrow patch:

1. **P1 — duplicate approval race:** the previous handler read pending state, invoked the relay and only then wrote an outcome, permitting concurrent requests to reach the relay. The patch durably claims a live pending intent using a journaled, majority-acknowledged atomic compare-and-set before any relay side effect. Approval and denial compete for the same pending state. Guarded terminal writes cannot overwrite another decision. Interrupted/uncertain signing becomes non-retryable internal signing/reconciliation state; no automatic reopening or rebroadcast is provided.
2. **P2 — same-client transaction-status isolation:** the previous partner status lookup omitted the token subject. The patched query requires intent ID, token audience/client and token subject/user together; foreign and absent intents share a Not found response. The platform backend independently constrains its own intent lookup to its session user.
